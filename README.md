# 仕訳日報管理Webアプリ

Excelで管理している「仕分け日報」「集計表」「月次作業日報」をWebアプリ化するための Next.js / TypeScript / Supabase / Tailwind CSS アプリです。

## 主な機能

- 仕訳日報の登録・編集・削除
- 担当者マスタ、クライアントマスタ管理
- 仕訳日報の月次集計とCSV出力
- 月次作業日報の登録・編集・削除
- 作業種別マスタ
  - 提出書類
  - その他事務業務
- 作業種別ごとの集計単位
  - 提出書類: 件数
  - その他事務業務: 時間
- 作業種別に応じた入力欄の出し分け
  - 提出書類: 書類数、メモ
  - その他事務業務: 作業時間（分）、メモ
- 月次作業集計
  - 対象月選択
  - 顧問先別集計
  - 作業種別別集計
  - 書類数合計、作業時間合計、金額合計
- 単価設定
  - 手入力: 初期値 1件あたり50円
  - スマート取込: 初期値 1件あたり10円
  - 提出書類: 初期値 1件あたり3,000円
  - その他事務業務: 初期値 10分あたり500円
- 顧問先別の月次請求額表示
  - 仕訳日報分
  - 提出書類分
  - その他事務業務分
  - 合計金額
- CSV出力
  - 仕訳日報CSV
  - 仕訳月次集計CSV
  - 月次作業日報CSV
  - 月次集計CSV
  - 顧問先別請求CSV

「個人別仕訳」と「その他仕訳」は、既存の仕訳日報機能と重複するため、月次作業日報の作業種別には含めていません。

## セットアップ

```bash
npm install
npm run dev
```

PowerShellで npm が実行ポリシーにより止まる場合は、Windows用の `npm.cmd` を使ってください。

```bash
npm.cmd install
npm.cmd run dev
```

## Supabase接続

1. SupabaseのSQL Editorで `supabase/schema.sql` を実行します。
2. `.env.example` を `.env.local` にコピーします。
3. `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` を設定します。
4. 開発サーバーを再起動します。

環境変数が未設定の場合は、ブラウザのローカルストレージに保存されます。既存のローカルデータがある場合でも、新しい月次作業日報用の初期データは自動で補完されます。

### 本番データ保護の注意

アプリ起動時やVercelデプロイ時に、Supabase上の担当者、顧問先、単価、共有リンク、支払明細書設定、日報データを初期化する処理は実行しません。アプリ起動時のSupabase処理は基本的に読み込みだけで、保存や更新は画面上で保存ボタンを押した場合のみ実行されます。

`supabase/schema.sql` はテーブル作成と不足カラム追加、初回用の最低限の初期行追加に使います。初期行の追加は `on conflict do nothing` を使っているため、既存データがある場合は上書きしません。

本番運用中は、`DROP TABLE`、`DELETE FROM`、`TRUNCATE` を含むSQLを実行しないでください。これらは既存データを削除します。リセットが必要な場合だけ、バックアップを取得したうえで、明示的にリセット用SQLを実行してください。

このプロジェクトには、画面上から全データを初期化するリセットボタンは用意していません。初期化が必要な場合は、管理者が意図してSQLを実行する運用にしてください。

## 請求計算

仕訳日報では、手入力件数に対してクライアントごとに月30件の無料枠を適用します。無料枠を超えた手入力件数とスマート取込件数の合計を、請求対象合計として表示します。

仕訳日報分の金額は、以下の初期単価で計算します。

- 手入力請求対象件数: 1件あたり50円
- スマート取込件数: 1件あたり10円

月次作業日報では、作業種別ごとの単価設定を使って金額を計算します。

- 提出書類: 書類数 ÷ 単位件数 × 単価
- その他事務業務: 入力分数 ÷ 単位分数 × 単価

例: その他事務業務が30分、単価が10分あたり500円の場合、`30 ÷ 10 × 500 = 1,500円` です。

## CSV出力の場所と使い方

各CSV出力ボタンは、対象画面の右上にあります。対象月を選択してからボタンを押すと、ブラウザでCSVファイルをダウンロードします。

| 画面 | ボタン名 | ファイル名 |
| --- | --- | --- |
| 仕訳日報一覧 | 仕訳日報CSV出力 | sorting_daily_report_YYYY-MM.csv |
| 仕訳月次集計 | 仕訳月次集計CSV出力 | sorting_monthly_summary_YYYY-MM.csv |
| 月次作業日報 | 月次作業日報CSV出力 | monthly_work_report_YYYY-MM.csv |
| 月次作業集計 | 月次作業集計CSV出力 | monthly_work_summary_YYYY-MM.csv |
| 顧問先別請求 | 顧問先別請求CSV出力 | client_billing_YYYY-MM.csv |

CSVは選択中の対象月で絞り込んだ内容を出力します。対象データが0件の場合もヘッダー行だけのCSVを出力します。CSV本文の先頭にはBOMを付けているため、Excelで開いたときに日本語が文字化けしにくくなっています。

CSV出力後は、画面上部に「CSVを出力しました」と表示されます。

## 支払明細PDFの使い方

1. 上部メニューの「外注費支払」を開きます。
2. 対象月を選択します。
3. 担当者別支払一覧で、PDFを出したい担当者の行をクリックします。
4. 明細欄の「支払明細PDF出力」ボタンを押します。
5. ブラウザの印刷画面が開くので、送信先で「PDFとして保存」を選びます。

PDFには、支払先名、対象月、発行日、発行者情報、支払予定日、備考、作業明細、外注費の内訳、支払合計が表示されます。ファイル名は `payment_statement_担当者名_YYYY-MM.pdf` になるよう、印刷画面のタイトルに反映しています。

- 発行者電話番号

保存した内容は、次回以降に出力する支払明細PDFへ反映されます。Supabaseを利用する場合は、`supabase/schema.sql` を実行して `payment_statement_settings` テーブルを作成してください。

## 作業入力画面の件数入力補助

作業入力画面の仕訳作業では、同じ顧問先の直近の仕訳日報から前回総仕訳数を取得し、以下の式で件数入力を補助します。

```text
今回作業件数 = 今回の総仕訳数 - 前回総仕訳数
手入力件数 + スマート取込件数 = 今回作業件数
```

3項目のうち2項目を入力すると、残り1項目を自動入力します。同じ顧問先の過去データがない初回入力の場合は、前回総仕訳数を0件として計算します。

| 入力した項目 | 自動入力される項目 |
| --- | --- |
| 今回の総仕訳数、スマート取込件数 | 手入力件数 = 今回の総仕訳数 - 前回総仕訳数 - スマート取込件数 |
| 今回の総仕訳数、手入力件数 | スマート取込件数 = 今回の総仕訳数 - 前回総仕訳数 - 手入力件数 |
| 手入力件数、スマート取込件数 | 総仕訳数 = 前回総仕訳数 + 手入力件数 + スマート取込件数 |

自動入力された欄には「自動計算」と表示されます。ユーザーが自動計算された値を手で修正した場合は、その値を優先し、自動上書きしません。

3項目すべてを手入力して合計が合わない場合は、以下の警告を表示します。

```text
今回作業件数と、手入力件数＋スマート取込件数が一致していません
```

計算結果がマイナスになる場合は、以下の警告を表示します。

```text
入力値を確認してください。計算結果がマイナスになります
```

保存時にも「今回の総仕訳数 - 前回総仕訳数」と「手入力件数＋スマート取込件数」が一致しているか確認します。初回入力の場合は前回総仕訳数を0件として扱うため、「今回の総仕訳数」と「手入力件数＋スマート取込件数」が一致していれば保存できます。一致していない場合は保存されません。

総仕訳数入力欄の下には、入力補助として「前回総仕訳数」と「今回作業件数」を小さな補足テキストで表示します。初回入力の場合は「前回総仕訳数：0件（初回） ／ 今回作業件数：1,000件」のように表示します。

## 外注者用共有リンク

外注者に管理画面全体を見せず、スマホから作業入力だけを行ってもらうための共有リンクを発行できます。パスコードやログインは使わず、共有リンクが有効なら入力可能、無効なら入力不可というシンプルな運用です。

### 共有リンクの発行方法

1. 管理画面で「その他」→「設定」→「担当者設定」を開きます。
2. 対象の担当者行にある「共有リンク発行」ボタンを押します。
3. `/worker/[token]` 形式の共有リンクURLが表示されます。
4. 「コピー」ボタンを押すと、共有リンクURLをクリップボードにコピーできます。

### 外注者への共有方法

コピーした共有リンクを、LINEやメールで外注者へ送ります。外注者はスマホのブラウザでリンクを開くだけで入力できます。

Supabaseを使っている場合は、別端末のスマホからも同じデータに登録されます。ローカル保存だけで動かしている場合、共有リンクは同じブラウザ内での確認用になります。

### 外注者がスマホから入力する方法

外注者用画面には以下だけが表示されます。

- 作業日
- 担当者名
- 顧問先
- 作業区分
- 総仕訳数
- 手入力件数
- スマート取込件数
- 書類数
- 作業時間（分）
- メモ
- 保存ボタン

担当者名は共有リンクに紐づく担当者で固定され、外注者側では変更できません。作業区分を選ぶと、必要な入力欄だけが表示されます。

仕訳作業では、管理者用画面と同じ計算式を使います。

```text
今回作業件数 = 今回総仕訳数 - 前回総仕訳数
手入力件数 + スマート取込件数 = 今回作業件数
```

保存後は「作業を登録しました」と表示され、同じ担当者のまま続けて入力できます。

### 共有リンクの無効化

「その他」→「設定」→「担当者設定」で、対象担当者の「無効化」ボタンを押すと共有リンクを停止できます。無効化されたリンクを開くと、以下のメッセージが表示されます。

```text
この入力リンクは現在利用できません
```

再度使う場合は「有効化」ボタンを押してください。

### 管理者側での確認

外注者用リンクから登録された作業も、通常の作業一覧、月次集計、外注費支払に反映されます。作業一覧には「登録元」列があり、以下のように表示されます。

- 管理者入力
- 外注者リンク入力（担当者名）

## Vercel公開手順

このアプリはNext.js標準構成のため、Vercelにそのまま公開できます。Vercel用の特別な設定ファイルは不要です。

### 事前準備

Supabaseで保存する前提のため、先に以下を済ませてください。

1. SupabaseのSQL Editorで `supabase/schema.sql` を実行します。
2. SupabaseのProject URLを確認します。
3. Supabaseのanon public keyを確認します。

Vercelに設定する環境変数は以下の2つです。

| 環境変数名 | 内容 |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | SupabaseのProject URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabaseのanon public key |

`.env.example` もこの2項目だけを使う形にしています。

### Vercelで公開する流れ

1. GitHubなどにこのプロジェクトをアップロードします。
2. Vercelで「Add New Project」を選びます。
3. アップロードしたリポジトリを選択します。
4. Framework PresetはNext.jsのままで進めます。
5. Environment Variablesに以下を追加します。
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
6. 「Deploy」を押します。

Build Commandは通常どおり `npm run build` で動きます。Windowsでローカル確認する場合は以下を使います。

```bash
npm.cmd run build
```

### 公開後の確認

公開URLを開き、画面上部の保存先が「Supabase」になっていることを確認してください。「ローカル」と表示される場合は、Vercelの環境変数が未設定、または値が間違っている可能性があります。

次に以下を確認します。

- 担当者設定で共有リンクを発行できる
- 共有リンクをコピーできる
- コピーしたURLが `https://公開ドメイン/worker/[token]` の形になっている
- スマホで共有リンクを開くと外注者用入力画面が表示される
- 外注者用画面から保存した作業が、管理画面の作業一覧・月次集計・外注費支払に反映される

共有リンクのコピー機能は、公開URLのドメインを使って自動的に `https://公開ドメイン/worker/[token]` をコピーします。そのため、Vercel公開後も外注者用リンクはそのまま利用できます。

### 注意点

外注者用共有リンクにはパスコードやログインを付けていません。信用できる外注先にだけ共有し、使わなくなったリンクは「担当者設定」から無効化してください。

### GitHub反映後のVercel確認

GitHubへpushすると、Vercel連携済みのプロジェクトでは自動デプロイが開始されます。

1. GitHubのリポジトリを開き、`README.md` と `TEST_REPORT.md` が反映されていることを確認します。
2. Vercelの対象プロジェクトを開きます。
3. Deploymentsで最新のデプロイが `Building` から `Ready` になるまで待ちます。
4. `Ready` になったら公開URLを開きます。
5. 画面上部の保存先が `Supabase` になっていることを確認します。
6. `TEST_REPORT.md` のチェック項目に沿って、管理者入力、外注者リンク入力、PDF、CSVを確認します。

公開URL:

```text
https://create-repository.vercel.app
```

もしVercelのデプロイが失敗した場合は、VercelのBuild Logsを開き、`NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` がProduction環境に設定されているか確認してください。

## 公開版の動作確認

Vercel公開版とSupabase保存版の確認には、`TEST_REPORT.md` を使ってください。

確認対象URL:

```text
https://create-repository.vercel.app
```

`TEST_REPORT.md` には以下の確認項目をまとめています。

- 公開URLでアプリが開くか
- 保存先がSupabaseになっているか
- 管理者画面から仕訳作業を登録できるか
- 更新後もデータが残るか
- 月次集計、外注費支払に反映されるか
- 外注者用共有リンクを取得できるか
- `/worker/[token]` で外注者用画面が開くか
- 外注者用画面に管理メニューが表示されないか
- 外注者リンク入力分が作業一覧に表示されるか
- 支払明細PDFとCSVを出力できるか
- 初回入力時、前回総仕訳数を0件として計算するか
- 前回総仕訳数がある場合の手入力件数と外注費が期待値どおりか

PlaywrightなどのE2Eテストは未導入です。追加する場合は、別途Playwrightの依存関係をインストールしてから設定してください。

## バックアップ管理

デプロイ前、コード修正前、単価や担当者設定を大きく変更する前は、先にバックアップを取得してください。

操作場所:

1. 「その他」を開きます。
2. 「バックアップ管理」を開きます。

### JSONバックアップ

バックアップ管理では、以下のJSONバックアップをダウンロードできます。

| ボタン | 内容 | ファイル名 |
| --- | --- | --- |
| 全データをバックアップ | 作業履歴と設定をすべて保存 | `backup_all_YYYY-MM-DD_HHmm.json` |
| 作業履歴だけバックアップ | 仕訳日報、月次作業日報を保存 | `backup_work_logs_YYYY-MM-DD_HHmm.json` |
| 設定だけバックアップ | 顧問先、担当者、単価、共有リンク、支払明細書設定を保存 | `backup_settings_YYYY-MM-DD_HHmm.json` |

JSONには、`backup_created_at`、`backup_schema_version`、仕訳日報、月次作業日報、顧問先、担当者、単価、担当者別外注単価、共有リンク、支払明細書設定が含まれます。

### CSVバックアップ

作業履歴は、Excelで確認しやすいCSVでもバックアップできます。CSVはBOM付きUTF-8で出力するため、Excelで日本語が文字化けしにくくなっています。

CSVバックアップ対象:

- 仕訳日報
- 月次作業日報
- 外注費支払明細
- 顧問先別集計

CSVバックアップは、画面で選択中の対象月をもとに出力します。

### バックアップ内容確認

「バックアップ内容確認」では、保存済みのバックアップJSONを選択して、中に含まれる件数を確認できます。

この画面では復元や上書きは実行しません。安全性を優先し、現在はバックアップ出力と内容確認のみ対応しています。

### ブラウザ内の直近バックアップ

作業入力を保存したタイミングで、このブラウザのlocalStorageにも直近バックアップを保存します。

保存内容:

- 最新の作業入力データ
- 担当者設定
- 顧問先設定
- 単価設定
- 担当者別外注単価

直近5世代まで保存します。バックアップ管理画面で、localStorage内に直近バックアップが存在するか確認できます。

### デプロイ前の推奨運用

1. 「その他」→「バックアップ管理」を開きます。
2. 「全データをバックアップ」を押します。
3. ダウンロードしたJSONをPC、Google Drive、OneDriveなどに保存します。
4. 必要に応じてCSVバックアップも出力します。
5. Vercelへデプロイします。
6. 公開URLで保存先がSupabaseになっていることを確認します。
7. 作業一覧、月次集計、外注費支払、設定が残っていることを確認します。

### Supabase本番データを初期化しないための注意

アプリ起動時やVercelデプロイ時に、Supabase上の既存データや設定を初期化する処理は実行しません。初期データが必要な場合も、既存データがない場合のみ追加する方針です。

本番運用中のSupabaseでSQLを実行する場合は、必ず事前にバックアップを取得してください。`schema.sql` に `DROP TABLE`、`DELETE FROM`、`TRUNCATE` などの破壊的なSQLを追加した場合、本番データが削除される可能性があります。そのようなSQLは本番運用では実行しないでください。

`supabase/schema.sql` は、テーブル作成、不足カラム追加、初回用の最低限の初期行追加に使います。初期行は `on conflict do nothing` を使い、既存の担当者、顧問先、単価、共有リンク、支払明細書設定、作業履歴を上書きしないようにしています。

### バックアップファイルの保管方法

バックアップJSONは、日付が分かるフォルダに保管してください。例:

```text
backup/
  2026-07-10/
    backup_all_2026-07-10_0930.json
    backup_sorting_reports_2026-07_2026-07-10_0930.csv
```

PC内だけでなく、Google DriveやOneDriveなど別の場所にもコピーしておくと、端末故障時のリスクを減らせます。
