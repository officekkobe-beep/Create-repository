## 2. 公開権限の危険箇所

1. **RLS が実質無効**: `supabase/schema.sql:340-353` で RLS 有効化後、`:359-479` の全14表のポリシーが `using (true)` / `with check (true)`（SELECT/INSERT/UPDATE/DELETE）。本番でも同状態＋`anon`/`authenticated` に TRUNCATE 含む権限付与を実測済み（Issue #3）。**CRITICAL**
2. **管理画面に認証なし**: `/` を開ければ全操作可能。外注者トークンも検証が事後。**CRITICAL**
3. **`schema.sql` 再実行で穴が復活する**: 各表が `drop policy if exists` → `create policy ... using (true)` の形（例 `:354-362`）。遮断後に誰かが現行 `schema.sql` を流すと権限が元に戻る。切替PRで `schema.sql` 側を先に直す必要がある。**MAJOR**
4. **確定月がDBで守られていない**: `isMonthClosed` はブラウザ保持データで判定。直接APIなら素通り。**MAJOR**
5. **過去月金額の不変性なし**: `lib/calculations.ts:276,286,370,460` と `app/page.tsx:543,595` が現在の `unit_prices.amount` から再計算。保存行に単価・金額スナップショットなし。単価改定で確定済み月の表示額が動く。**MAJOR**
6. **既存計算の前提（変えない）**: `unitQuantityFor` は件数=1／時間=10 固定（`calculations.ts:65-67`）。`unit_prices.quantity/unit_label` は金額計算で使わない。新30分料金を既存列に載せない。
7. **テスト基盤が無い**: `package.json` に test スクリプト・テストファイルなし。計算の回帰を守る手段が現状ゼロ。

### 3.1 管理者認証（最小構成・提案）
- 環境変数 `ADMIN_PASSWORD` と `SESSION_SECRET`（サーバーのみ、`NEXT_PUBLIC_` 禁止）。ログイン画面1枚 → 署名付き HttpOnly Cookie（有効期限つき）。`middleware.ts` で `/`・`/api/admin/*` を保護。
- Supabase Auth は採用しない（利用者1名・手間最小の方針、導入・運用コストが大きい）。外部IdP・ユーザー管理画面も作らない。

### 3.2 外注者API（最小応答）
- `GET /api/worker/[token]`: サーバーでトークン照合 → **自分の担当者名・有効顧問先（名称/決算月）・有効作業種別（名称/単位）・確定月一覧・前回総仕訳数の算出に必要な最小情報だけ**返す。単価・外注費・他担当者・監査ログ・他トークンは返さない。
- `POST /api/worker/[token]/reports`: 担当者IDは**トークンから決定**（リクエストの値を信用しない）。確定月拒否・件数整合・対象年度内の総仕訳数逆転拒否（現行クライアント検証 `worker/[token]/page.tsx:195-197` をサーバーにも移す）。

### 3.3 管理者の保存API
- 「名前付きコマンド」を1操作1ハンドラで実装（例: 日報保存/削除、月次確定/解除、マスタ更新、トークン発行）。**テーブル名・フィルタを受け取る汎用プロキシは作らない**。
- 確定月の判定は**DBの `monthly_closings` をサーバーで読む**（クライアント渡しの `AppData` を信用しない）。

### 3.4 外注者の入力ミス対策（優先度高。PR-3 に含める）
| 対策 | 内容 | 判定の置き場所 |
|---|---|---|
| 確定月の拒否 | 作業日の属する月が確定済みなら保存不可（既存文言を維持） | サーバー |
| 重複 | 同一 担当者×顧問先×作業日×作業種別×数量 が既存にあれば「重複の可能性」確認（強制拒否はしない） | サーバー判定＋画面で確認ダイアログ |
| 異常値 | 当該 顧問先×作業種別 の過去実績に対する大幅超過で確認ダイアログ（**閾値はユーザー決定事項**、§6） | サーバー判定＋確認 |
| 件数整合/年度逆転 | 既存ルールをサーバーでも検証 | サーバー |
| 修正履歴 | 外注者には編集/削除を持たせない（誤りは管理者が修正→既存の `audit_logs` 記録）。外注者が登録した行は `source=worker_link` で区別済み | 既存機能 |

## 4. 切替（計画停止）案と Go / No-Go

**停止枠は未決（作業前に報告・合意）。** 目安は「PR-4完了後、半日以内」。

手順（各ステップ完了を確認してから次へ）:
1. **事前**: 外注者へ停止日時と代替受付方法を連絡。管理者パスワード・`SESSION_SECRET` を決定し Vercel 環境変数に登録（`SUPABASE_SERVICE_ROLE_KEY` 含む。値はチャット/Issue/PR/ログに出さない）。
2. **バックアップ**: アプリの全データJSON＋CSV（`lib/backup.ts`）に加え、**`monthly_closings`・`audit_logs`・`backup_records` は JSON に含まれない**ため Supabase ダッシュボード側のバックアップ/エクスポートも取得。取得ファイルの件数を現行画面と突合。
3. **停止開始** → 入力が止まった状態で最終バックアップ。
4. **SQL実行**（PR-4で用意したレビュー済みSQL）: `drop policy if exists`（`using(true)` 系のみ）→ `revoke ... from anon, authenticated`。**データを変更するSQL（DELETE/TRUNCATE/DROP TABLE）は含めない。**
5. **トークン**: 旧トークンを全失効 → 新トークン発行 → 管理画面から外注者へ配布。
6. **疎通確認**: 管理者ログイン→一覧表示／外注者の新リンク→登録→一覧に反映／確定月の拒否。
7. **直接API拒否の確認**（§5 の C 群）。通れば再開。

**Go**: PR-1〜PR-4 マージ済み／テスト合格／バックアップ取得・件数突合済み／ユーザーが日時を承認／外注者へ連絡済み。
**No-Go**: 上記のいずれかが欠ける／疎通確認が失敗。
**ロールバック方針**: **公開権限（anon全開放）へは戻さない**（AI Council #177）。不具合は新経路側を前方修正。データ破損時のみバックアップから個別復元（復元機能は無いため手作業SQL。手順は切替前に別途用意）。

**停止中の代替受付**: 外注者は LINE/メール等で「作業日・顧問先・作業種別・数量(または時間)」を管理者へ連絡 → 再開後に管理者が入力（`source` は管理者入力になる点を許容）。

**`keep-alive` Cron の扱い**: anon で `clients` を読んでいる（`route.ts`）ため、遮断後は 500 になり無料枠の自動停止対策が失効する。PR-4 でサーバー鍵を使う実装に変更し、切替後の疎通確認に含める。

## 5. テスト計画（合格／不合格／未実施で記録）

**現状: 自動テストなし（すべて未実施）。** PR-1 で `vitest` を導入して下記を整備する。

**A. 計算の回帰（既存を変えないことの固定）**
- 件数=1・時間=10 の換算、`Math.round` の境界（例: 5分×500円/10分=250、1分=50、3分×500/10=150）
- 外注費の優先順位: 担当者×作業種別 → 作業種別デフォルト → 0（0円と未設定を区別）
- 仕訳: 無料枠30件、手入力→スマート取込の控除順、対象年度ごとの前回総仕訳数、年度境界（決算月3月/7月）
- `unit_prices.quantity` に異常値があっても金額が変わらない

**B. サーバー検証（PR-3）**
- 確定月への登録/編集/削除を拒否、日付を確定月へ移す編集も拒否（元月・先月の両方を確認）
- 総仕訳数が前回を下回る、件数と内訳の不一致、数量0以下を拒否
- 重複・異常値は確認ダイアログ → 承認後に保存
- 外注者トークンで他担当者の行・単価が取得できない／他人IDで保存できない

**C. 直接API拒否（切替後・PR-4の検証スクリプトで実行）** ※`anon` 公開キーで、応答コードとエラーのみ記録し**データ行は出力しない**
- 全14表について SELECT/INSERT/UPDATE/DELETE が権限エラー（401/403）になる
- TRUNCATE 権限がない
- 旧共有トークンで `/api/worker/<旧>` が 404/403、新トークンは成功
- 認証なしで `/api/admin/*` が 401、`/` がログイン画面へ

**D. 画面の回帰（ユーザー画面確認）**
- 日報入力→確認モーダル→保存、編集/削除モーダル、月次確定/解除、CSV/JSON出力が切替前後で同一結果
